Reinforcement Learning: learning from interaction

Reinforcement Learning (RL) is a branch of machine learning in which an agent learns how to behave by interacting with an environment. The agent takes actions, receives rewards, and updates its strategy to maximize long-term cumulative reward.

What is RL?

In RL, the agent is not told the correct action in advance. Instead, it explores the environment, observes the consequences of each action, and learns which actions lead to better outcomes over time. This is similar to how humans learn by trial and error.

At each time step t, the agent observes a state s , selects an action a, receives a reward r, and moves to a new state s. The agent tries to learn a policy that makes future rewards as large as possible.

MDP properties

The standard mathematical model for RL is a Markov Decision Process (MDP). An MDP is defined by a set of components that describe interaction between the agent and its environment.

Component Meaning
S State space: all possible situations the agent can be in.
A Action space: all actions available to the agent.
P Transition function: probability of moving to a next state and reward after an action.
R Reward function: the immediate feedback received after taking an action in a state.
γ Discount factor: trades off immediate reward vs future reward.
π Policy: the strategy the agent uses to select actions.
P(s', r | s, a) = probability of transitioning to next state s' and receiving reward r when action a is taken in state s

The Markov property means that the future depends only on the current state and action, not on the full history of how the agent arrived there. In other words, once we know the current state, the rest of the past is not needed for future decisions.

Objective

The agent's goal is to maximize the expected cumulative reward, also called the return.

G_t = r_{t+1} + γ r_{t+2} + γ² r_{t+3} + ... = Σ_{k=0}^{∞} γ^k r_{t+k+1}

A discount factor γ ∈ [0,1] makes rewards farther in the future less important than immediate rewards. This helps the agent trade off short-term reward and long-term planning.

Value-based methods

Value-based methods learn value functions and then choose actions that lead to the best estimated return. These methods do not explicitly learn a policy function; instead, they estimate how good each state or state-action pair is.

State value

V(s) estimates how good it is to be in a state, assuming the agent follows a given policy afterward.

Action value

Q(s, a) estimates how good it is to take action a in state s.

Decision rule

The agent chooses the action with the highest estimated action value, often called the greedy action.

Q(s, a) = expected return after taking action a in state s and following the optimal policy thereafter

The Q comes from “the Quality” of that action at that state — it represents the value of taking action a in state s. In Q-learning, the core idea is to estimate Q(s, a) values directly from interaction data. This makes it a classic model-free, value-based algorithm because it does not require a model of the environment's transition probabilities.

Why value-based methods are useful
  • They learn a compact estimate of expected future reward.
  • They work well when the action space is moderate and the environment is not fully known.
  • They form the basis for algorithms such as Q-learning and SARSA.
Bellman equations

Bellman equations express the idea that the value of a state can be written in terms of the immediate reward plus the discounted value of the next state. They are the foundation of many RL algorithms, including dynamic programming and TD methods.

V(s) = Σ_{a} π(a|s) Σ_{s', r} P(s', r | s, a) [r + γ V(s')]

This is the Bellman expectation equation. It says that the value of a state is the expected immediate reward plus the discounted value of the next state, weighted by the policy and the environment dynamics.

Q*(s, a) = Σ_{s', r} P(s', r | s, a) [r + γ max_{a'} Q*(s', a')]

This is the Bellman optimality equation for action values. It defines the optimal action-value function as the expected reward of taking action a now, plus the best future action from the next state.

V*(s) = max_a Σ_{s', r} P(s', r | s, a) [r + γ V*(s')]

The optimal policy is the one that chooses actions with the highest value in every state. In practice, RL agents do not usually know the exact transition model, so they learn these values from samples gathered while interacting with the environment.

Monte Carlo VS Temporal DIfference

Remember that an RL agent learns by interacting with its environment. The idea is that given the experience and the received reward, the agent will update its value function or policy.

Monte Carlo and Temporal Difference Learning are two different strategies on how to train our value function or our policy function. Both of them use experience to solve the RL problem.

On one hand, Monte Carlo uses an entire episode of experience before learning. On the other hand, Temporal Difference uses only a step (St, At, Rt+1, St+1) to learn.

Key difference
  • Monte Carlo: learns after the full episode is completed.
  • Temporal Difference: learns immediately from each transition using the current experience.
Monte Carlo Learning

Monte Carlo: learning at the end of the episode

Monte Carlo waits until the end of the episode, calculates Gt (return) and uses it as a target for updating V(St).

So it requires a complete episode of interaction before updating our value function.

G_t = R_{t+1} + R_{t+2} + R_{t+3} + ...
Monte Carlo

We always start the episode at the same starting point.
The agent takes actions using the policy. For instance, using an ε-greedy strategy, a policy that alternates between exploration (random actions) and exploitation.

We get the reward and the next state. We terminate the episode if the cat eats the mouse or if the mouse moves more than 10 steps.

At the end of the episode, we have a list of (state, action, reward, next_state) tuples, for example: [[State tile 3 bottom, Go Left, +1, State tile 2 bottom], [State tile 2 bottom, Go Left, +0, State tile 1 bottom], ...]

The agent will sum the total rewards Gt to see how well it did. It will then update V(st) based on the formula.

Update rule
V(S_t) ← V(S_t) + lr × [G_t − V(S_t)]

Then start a new game with this new knowledge. By running more and more episodes, the agent will learn to play better and better.

Example

Suppose we train a state-value function using Monte Carlo.

  • We initialize our value function so that it returns 0 value for each state.
  • Our learning rate (lr) is 0.1.
  • Our discount rate is 1 (so there is no discount).
  • The mouse explores the environment and takes random actions.

The mouse made more than 10 steps, so the episode ends.

We have a list of state, action, reward, next_state. We need to calculate the return:

G_t = R_{t+1} + R_{t+2} + R_{t+3} + ...
G_0 = R_1 + R_2 + R_3 + ... = 1 + 0 + 0 + 0 + 0 + 0 + 1 + 1 + 0 + 0 = 3

We can now compute the new V(S0):

V(S_0) = V(S_0) + lr × [G_0 − V(S_0)]
V(S_0) = 0 + 0.1 × [3 − 0] = 0.3

After many episodes, the agent learns which states are better and updates its estimate of the value function accordingly.

Temporal difference learning

Temporal Difference (TD) learning combines ideas from Monte Carlo methods and dynamic programming. It updates value estimates using the difference between the current estimate and a better estimate formed from observed data.

Q(s, a) ← Q(s, a) + α [r + γ max_{a'} Q(s', a') - Q(s, a)]

This is the classic Q-learning update. The term inside brackets is the TD error:

  • r + γ max Q(s', a') is the target estimate from the next state.
  • Q(s, a) is the current estimate.
  • α is the learning rate.
Why TD is important
  • It learns online, without waiting for the full episode to finish.
  • It can be applied in continuing environments where tasks do not end cleanly.
  • It combines immediate feedback with bootstrapped estimates from future states.

This lab focuses on value-based TD methods and especially Q-learning, which is one of the most widely used RL algorithms. We are skipping policy-based methods and Monte Carlo-only approaches in this lab.

Q-learning recap

Q-learning is the reinforcement learning algorithm that trains a Q-function, an action-value function stored in memory as a Q-table. For a given state and action, the Q-function looks up the corresponding value in the table.

Q(s, a) = expected cumulative reward when taking action a in state s and then following the optimal policy thereafter

The Q stands for quality: it is the value of taking a particular action in a given state. In other words, Q(s, a) tells us how good that action is right now.

At the start, the Q-table is often initialized to zeros or arbitrary values, so it is not very useful. As the agent interacts with the environment and updates its table, the estimates become better and better approximations of the true action values.

A simple Q-learning example

Imagine a mouse in a small maze. It always starts at the same point and tries to reach the big pile of cheese while avoiding poison. The episode ends if it eats poison, reaches the cheese, or exceeds the step limit.

  • +1: small cheese
  • +10: large cheese
  • -10: poison
  • +0: empty cell or too many steps

The agent learns by trying actions, receiving rewards, and updating Q(s, a) values. Over time, it learns that some actions lead to higher long-term reward than others, and it builds an optimal policy that prefers the best actions in each state.

Q-table

Stores the estimated value for each state-action pair, enabling quick lookup during learning and decision making.

Exploration

The agent tries actions it has not tried much to discover better outcomes and improve the Q-table.

Optimal policy

Once the Q-function is good enough, the best action in each state is the one with the maximum Q-value, argmax_a Q(s, a).

Why this matters
  • Q-learning is model-free: it does not need a model of the environment dynamics.
  • It is off-policy: it learns the optimal policy while following exploratory behavior.
  • It updates values using bootstrapping from the next state, which is the essence of temporal-difference learning.
  • When the Q-table converges, the greedy policy based on it becomes optimal.
Q-learning update
Q(s, a) ← Q(s, a) + α [r + γ max_{a'} Q(s', a') - Q(s, a)]

This update says: move the current estimate toward a better target using the observed reward and the best estimated value from the next state. The difference between the target and the current estimate is the TD error.

Q-learning pseudocode
Initialize Q(s, a) arbitrarily for all s, a
For each episode:
    Initialize state s
    Repeat for each step in the episode:
        Choose action a from state s using an exploration strategy (for example, ε-greedy)
        Take action a, observe reward r and next state s'
        Q(s, a) ← Q(s, a) + α [r + γ max_a' Q(s', a') − Q(s, a)]
        s ← s'
    Until s is terminal

In short, Q-learning learns from experience by repeatedly updating state-action values. Through enough exploration and learning, the agent eventually discovers which actions maximize long-term reward and acts accordingly.

SARSA VS Q-Learning

SARSA (State-Action-Reward-State-Action) is an on-policy, model-free Reinforcement Learning (RL) algorithm used to learn the value of actions in a Markov Decision Process (MDP). Its name directly reflects the 5-tuple experience sequence used in its update rule:

(St, At, Rt+1, St+1, At+1)

On-policy vs. off-policy (SARSA vs. Q-Learning): The defining feature of SARSA is that it is on-policy. It updates its Q-value based on the action actually taken (At+1), including exploratory or suboptimal moves. In contrast, Q-Learning is off-policy because it updates assuming the best possible future action (maxa Q(St+1, a)) is taken regardless of what the agent actually chooses next.

Feature SARSA (On-Policy) Q-Learning (Off-Policy)
Target Update Rt+1 + γQ(St+1, At+1) Rt+1 + γ maxa Q(St+1, a)
Policy Assumed Current exploration policy (includes randomness and mistakes) Optimal target policy (greedy choice)
Risk Profile Safer / Conservative in risky environments with penalties Aggressive / Optimistic, assumes flawless future execution
Convergence Speed Slower in some settings because it includes exploratory penalties Faster in many cases because it targets the best possible future value
Why SARSA is often preferred
  • Safe exploration: It accounts for exploratory mistakes in environments with penalizing states.
  • Practical safety: It is often preferred when safety, risk reduction, and real online performance during learning matter more than finding the shortest theoretical path.

It is worth clarifying that SARSA still aims to learn an optimal policy, but it optimizes for the actual operating environment, which includes the fact that the agent occasionally makes exploratory mistakes or encounters unexpected noise.

Why SARSA works better in risky settings

Q-Learning assumes the agent will act flawlessly in the future (maxa Q(S', a)). If taking a step next to a hazard offers a huge reward, Q-Learning chooses it even if a slight mistake or exploratory step will drop the agent into catastrophic failure.

SARSA factors in the actual action (A') chosen by the current policy. Because the agent occasionally explores with an ε-greedy policy, it may randomly pick a dangerous action. SARSA therefore learns that being close to hazards is dangerous during training and automatically learns a safer buffer path.

In stochastic environments—especially where mistakes carry high penalties—SARSA consistently outperforms Q-learning during online execution.

Policy Target Theoretical Maximum Yield Practical Expected Value
Q-Learning Highest optimistic value under ideal behavior Can be lower in real risky settings because exploration may trigger penalties
SARSA More conservative theoretical optimum Higher practical expected value when mistakes are costly
Concrete example: autonomous robot delivery in a warehouse

Imagine an autonomous delivery robot carrying fragile glass components through a busy manufacturing warehouse.

The scenario

  • Shortest path (ledge): A narrow path right along the edge of an open maintenance pit.
  • Reward: +100 for fast delivery.
  • Hazard: Falling into the pit costs -1000 and destroys the robot.
  • Safer path (main hallway): A slightly longer path around the safe central corridor.
  • Reward: +90 for fast delivery, taking 2 extra seconds.

Q-Learning (Off-Policy):

It learns that the narrow ledge is theoretically fastest and assigns it the highest value because maxa Q(S', a) assumes the robot will never make a mistake. In practice, during training or under slight sensor noise, the random exploration chance causes the robot to misstep off the ledge, triggering severe penalties and physically damaging the equipment.

SARSA (On-Policy):

Because SARSA evaluates Q(S', A'), it accounts for the chance that the robot might choose a risky exploratory action into the pit. The huge negative penalty (-1000) drags down the expected value of being anywhere near the ledge. It therefore learns that the ledge is too dangerous under real operating conditions and steers the robot through the wider safe hallway, delivering goods consistently without destroying hardware.

Real-world domains where SARSA is preferred
  • Robotics and physical systems: Preventing mechanical wear, motor burnout, or hardware crashes during live trial-and-error training.
  • Industrial process control / chemical plants: Preventing sudden spikes into dangerous temperature or pressure zones during optimization.
  • Autonomous driving: Keeping a comfortable safety buffer away from lane edges or tight traffic gaps.
